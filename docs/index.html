A.T Matrix Studio · 研究原型

一個操作介面，
連接不同形態的機械人。

ARGUS 以 VR 視覺、Leader Arms 及腳踏板構成操作端，並透過 dimOS 連接影像、感測器和機械人控制。目標是讓操作員按任務切換平台，在自動系統未能處理的情況下安全接管。

了解系統架構查看實際進度

目前屬研究及整合階段：VR 串流和部分感測器讀數已完成；通用控制映射、多機協作及現場可靠性仍待逐項驗證。

01 / 核心定位

ARGUS 研究的是跨平台操作層。

機械人有不同底盤、手臂和感測器。ARGUS 嘗試為操作員建立一致體驗，同時承認每個平台都需要獨立適配與安全測試。

同一套 VR、手臂和腳踏輸入，會按照機械人的能力重新映射。ARGUS 不是另一部機械人，而是逐步擴展的操作入口。
操作員端

VR 呈現機械人視角；Leader Arms 對應可操作機械臂；腳踏板負責移動或指定任務輸入。

連接與控制端

以 dimOS 作資料與命令連接基礎，逐台建立能力描述、指令映射、狀態回傳及安全限制。

核心驗證問題

在甚麼任務中，ARGUS 能比螢幕和手掣更快、更準或更容易學習？答案需要任務測試，而不只是沉浸感。

02 / 系統架構

由人的動作，到機械人的行動。

以下是目標架構。每一層代表清晰的開發責任；不表示所有平台已經完成端到端控制。

INPUT 01

操作輸入

VR 頭部方向、Leader Arms 姿態，以及腳踏板移動指令。

MAPPING 02

ARGUS 映射層

按照機械人能力轉換指令，管理速度限制、控制權及停止條件。

BRIDGE 03

dimOS 連接層

承接串流、感測資料及控制通道；每種機械人需要建立或調整適配器。

ROBOT 04

機械人平台

Aloha Mini、四臂移動平台、Unitree Go2，以及正在組裝的 Pupper V3 和 Open Duck Mini。

回傳操作員：攝影機畫面、感測器讀數、機械人狀態和操作回饋。目前已驗證 VR 串流及部分感測器資料讀取。
已驗證：原型可展示整合中：正在接駁或測試規劃中：未完成端到端驗證
03 / 機械人組合

以不同機體驗證同一操作概念。

團隊會先證明單一平台可以可靠運作，再量度增加新機械人所需的時間和修改。

硬件研究／接駁中

Aloha Mini

雙 SO-101 機械臂、升降結構及全向輪底盤，適合近距離室內雙臂操作研究。

驗證重點 · 雙臂姿態映射、升降及底盤控制。
自建平台／整合中

四臂移動平台

由 Aloha Mini 研究延伸，使用較大型自購車底和四隻 SO-101 機械臂，探索長距離移動與多臂操作。

驗證重點 · 四臂控制分配、同步及防碰撞。
機體已有／連接開發中

Unitree Go2

四足巡查和遙距視覺展示平台；團隊正以 dimOS 開發資料及控制連接。

驗證重點 · 穩定串流、狀態監察及異常時人手接管。
組裝中

Pupper V3

小型四足研究平台，用來比較另一套四足接口並檢驗控制層的可移植性。

下一步 · 完成硬件後定義基礎動作與回傳資料。
組裝中

Open Duck Mini

雙足角色機械人平台，用於探索肢體表達、平衡控制和具身互動。

下一步 · 先完成安全動作，再評估 ARGUS 控制適配。
平台擴展原則

能力導向適配

接入新機械人時，先識別影像、移動、手臂、感測及停止能力，再決定 cockpit 中哪些模組有實際用途。

原則 · 接上 dimOS 不等於即插即用。
04 / ROBOT-AR 整合

第一套已公開程式的移動操作平台。

學生開發的 Robot-AR bridge 已整合至主 repository，並保留作者及來源 commit。現有程式以雙臂配置為基線，四臂控制仍需另行設計和驗證。

Software prototype · Hardware validation pending

Robot-AR Bridge

以 NVIDIA Jetson Thor、四輪轉向車底及 SO-101 機械臂為目標平台。Bridge 將硬件存取集中在 HTTP 介面後，提供網頁遙控、命令解析、狀態回傳和安全停止。

安全預設只綁定 localhost；遙距開發使用 SSH tunnel
尚未完成Camera perception、VLA 操作、四臂同步

06 / 研發路線

以可量度的示範逐步證明價值。

由可靠單機閉環開始，再擴展至雙臂、多臂和不同機體；每一步都保留可檢查的驗收證據。

STEP 01

Go2 視覺與狀態基線

整理影像、感測器、電量和連線狀態，記錄延遲及斷線行為。

驗收：可重複完成同一段巡查示範。
STEP 02

人手接管閉環

建立操作權交接、移動限制和緊急停止，並比較一般介面與 cockpit。

驗收：遇上指定異常時能安全接管。
STEP 03

Robot-AR 實機閉環

驗證車底、雙臂和 Web bridge，再為四臂平台設計控制分配和防碰撞。

驗收：完成定義清楚的移動操作任務。
STEP 04

擴展至新機體

為 Pupper V3 和 Open Duck Mini 建立能力表及適配器，量度可重用部分。

驗收：新增平台的時間和改動可量度。

08 / 下一輪 Pitch

示範需要回答一個核心問題。

下一輪驗證

甚麼時候值得使用 ARGUS cockpit？

選擇一項真實任務，比較螢幕／手掣與 VR／Leader Arms／腳踏板的完成時間、錯誤、學習時間和操作員負擔。

  1. 使用相同任務和操作員條件。
  2. 記錄時間、成功率及安全事件。
  3. 只保留具有明確效益的控制模組。
